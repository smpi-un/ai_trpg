# シナリオ開発者向けガイド

このドキュメントは、プログラミングの知識がない方でも、このTRPGの新しいシナリオ、ルール、登場人物（NPC）などを追加・編集できるようにするためのガイドです。

すべてのゲーム内容は `gamebook/` というディレクトリの中にあるMarkdownファイル（`.md`）を編集するだけで変更できます。

## 1. gamebookディレクトリの構造

`gamebook/` ディレクトリには、主に以下のファイルが含まれています。

- `rule.md`: ゲームの基本的なルールを記述します。
- `scenario.md`: ゲームの物語、登場人物、場所、アイテムなどを記述します。
- `base.md`: （現在は未使用ですが、将来的に普遍的な設定などを記述する可能性があります）

## 2. ルールの編集 (`rule.md`)

このファイルには、ゲームマスター(AI)が従うべき普遍的なルールを記述します。

例えば、「判定はダイスで行う」「プレイヤーの行動を待たずに行動しない」といった、ゲームの根幹に関わるルールです。

通常のテキストと同じように、Markdown形式で自由に記述・編集してください。AIはここに書かれた内容を解釈し、ゲームマスターとしての振る舞いを調整します。

**記述例:**
```markdown
# ゲームの進行ルール

ゲームは以下のステップで進行します。

1.  **[描写]**: あなた（GM）は、現在の状況、風景、登場人物（NPC）の様子を詳細に描写します。
2.  **[行動確認]**: あなたは必ずプレイヤーに「あなたはどうしますか？」または「何をしますか？」と問いかけ、行動の宣言を待ちます。
```

## 3. シナリオの編集 (`scenario.md`)

このファイルが、ゲームの物語そのものです。Markdownの「見出し(`##`)」と「リスト(`*`)」を使って、構造的に記述します。

### 3.1. 基本構造

シナリオは大きなセクション（章）に分かれています。セクションは `##` で始まる見出しで定義します。

**主なセクション:**

- `## 1. シナリオ概要`: 物語のタイトルやあらすじを書きます。
- `## 2. ルールセット`: このシナリオ特有のルール（判定方法など）を書きます。
- `## 3. 登場NPCリスト`: 登場するキャラクターの情報を書きます。
- `## 4. シーン構成（章立て）`: ゲームの舞台となる場所やイベントを時系列で書きます。
- `## 5. アイテムリスト`: ゲームに登場するアイテムの情報を書きます。

### 3.2. NPCの記述方法

`## 3. 登場NPCリスト` のセクションに、`*` を使ってキャラクターを一人ずつ記述します。

`**[NPC名]**` のように、名前を太字で書くのが推奨です。

**記述例:**
```markdown
## 3. 登場NPCリスト
* **[執事のアルフレッド]**: 
    * **外見**: 背の高い、痩せた老人。常に無表情。
    * **性格**: 忠実だが、何かを隠している。
    * **口調**: 「旦那様は...そのような方ではございませんでした。」
    * **秘密**: （GM情報）彼は主人が研究していた古代の遺物の危険性を知っており、プレイヤーを屋敷から追い出そうとしている。
```

### 3.3. 場所やイベントの記述方法

`## 4. シーン構成（章立て）` のセクションに、`*` を使って場所やイベントを記述します。

場所やイベントには、AIが解釈しやすいように `[キーワード]` を含めることができます。

**記述例:**
```markdown
## 4. シーン構成（章立て）
* **導入**: プレイヤーが屋敷に到着する。執事アルフレッドが出迎える。
* **第1章：屋敷の探索**
    * **場所1（書斎）**: [描写のヒント] 本が散乱している。[調査判定（成功）] 隠された日記を発見する。[日記の内容] ...
    * **場所2（地下室）**: [描写のヒント] かび臭い。奥に祭壇のようなものがある。[イベント] もし祭壇に触れたら、罠が作動する（回避判定）。
```

AIは、プレイヤーが「書斎を調べる」と入力すると、この `場所1（書斎）` の記述を検索し、`本が散乱している` という描写をしたり、`調査判定` を促したりします。

## 4. 高度なシナリオ作成

### 4.1. 能力値チェックの実装

プレイヤーの行動の成否を、キャラクターの能力値とダイスロールによって判定させることができます。

シナリオに `判定` というキーワードと、どの能力値で、どのくらいの難易度かを記述します。

**記述例:**
```markdown
* **[木箱を腕力で開ける]**: プレイヤーが木箱を破壊しようとした場合。
    * **描写**: あなたは木箱を床に叩きつけ、破壊しようと試みる。
    * **判定**: **腕力**で能力値チェック。目標値は**10**。
    * **(成功)**: 激しい音を立てて木箱は砕け散り、中から古びた[鍵]が転がり出た。
    * **(失敗)**: 木箱は頑丈で、あなたの力ではびくともしない。手が少し痛む。
```

AIはこの記述を読み取り、憲法（ルール）に従って自動的に能力値チェックを実行し、成功か失敗に応じた描写を行います。

### 4.2. 世界の状態（フラグ）管理

「扉の鍵が開いているか」「特定のスイッチが押されているか」など、ゲーム世界のオブジェクトの状態を記憶させ、それによってAIの描写を変化させることができます。

これには `[MCP_UPDATE: ...]` というトリガーを使います。

**記述例:**
```markdown
* **[扉を鍵で開ける]**: プレイヤーが鍵で扉を開けた場合のイベント。
    * **描写**: 鍵を鍵穴に差し込んで回すと、カチャリという確かな手応えがあった。...
    * **トリガー**: [MCP_UPDATE: update_data("world", '"door_locked"', 'false')] [MCP_UPDATE: set_current_scene("end")]
```

この `トリガー` は、AIに対して「このイベントが発生したら、`world` にある `door_locked` という状態を `false` に変更せよ」と指示します。

その後、扉を調べた際の描写を、この状態に応じて変化させることができます。

**記述例:**
```markdown
* **[扉]**: 金属製の重々しい扉。ドアノブはあるが、[MCP: get_data("world", "door_locked")] の状態によって描写が変わる。もしロックされていればガチャガチャと音を立てるだけだが、開いていれば外に通じている。
```

AIは `get_data` で現在の状態を判断し、描写を自動的に切り替えます。

## 5. 新しいシナリオの作成

全く新しいゲームを作りたい場合は、既存の `scenario.md` の内容をすべて消去し、上記セクションを参考に新しい物語を記述してください。

AIはこのファイルに書かれた内容を読み込んで、あなただけのTRPGを即座にプレイヤーに提供します。
