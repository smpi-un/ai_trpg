# 開発者向けガイド

このドキュメントは、このTRPGアプリケーションのソースコードを改修・メンテナンスする開発者（AIを含む）を対象としています。
今後の開発を円滑に進めるため、特に**設計思想**と**アーキテクチャ**を深く理解してください。

## 1. 設計思想：AI-GMの3層アーキテクチャ

このアプリケーションは、AIゲームマスター(GM)の思考と記憶を、以下の3つの情報レイヤーに分離するという思想に基づいています。これにより、AIの応答の安定性と、ゲームデータの管理の容易性を両立させています。

- **レイヤー1 (L1): 憲法 (Constitution)**
  - **役割**: AI-GMの**不変の行動原理**。OSや人格に相当します。
  - **責務**: 「GMとしてどう振る舞うべきか」「どう思考し、応答すべきか」という根本的なルールを定義します。
  - **実装**: `src/policy.py` の `Constitution` クラスが担当します。AIに渡す最終的なプロンプトの骨格（テンプレート）を生成します。

- **レイヤー2 (L2): MCP (Memory Control Program)**
  - **役割**: ゲームの**動的な状態**を管理する短期記憶。RAMに相当します。
  - **責務**: プレイヤーのHP、持ち物、現在の場所、敵の状態、**能力値**など、ゲーム中に刻々と変化する情報を保持・更新します。また、扉の開閉状態といった**世界の状況(World State)**もここで管理します。
  - **実装**: `src/model.py` の `MCP` クラスが担当します。そのメソッドはAIが直接呼び出せる**ツール（関数）**として `controller` に提供されます。

- **レイヤー3 (L3): ゲームブック (Gamebook)**
  - **役割**: **静的なデータ**を格納する長期記憶。HDDや辞書に相当します。
  - **責務**: シナリオ、場所の描写、NPCのセリフ、基本ルールなど、ゲームの根幹となる変化しない情報を提供します。
  - **実装**: `src/gamebook.py` の `GameBook` クラスが担当し、`gamebook/` ディレクトリ配下のMarkdownファイルを解析・検索可能にします。

## 2. 処理フロー

プレイヤーの1回の入力に対し、システムは以下の流れで処理を行います。

0.  **ゲーム開始時 (`engine.py` & `controller.py`)**: 
    a. `create_character`メソッドが呼び出され、AIがダイスロールと`update_data`ツールを使ってプレイヤーの初期能力値を決定します。
    b. このプロセスはAIによって描写され、プレイヤーに提示されます。

1.  **入力受付 (`engine.py`)**: プレイヤーからの入力を受け取ります。
2.  **思考 (`controller.py`)**: `AI_ControllerMCP`が中心となり、以下の情報を収集します。
    a. **L2**: `MCP`から現在のゲーム状態を取得します。
    b. **L3**: `GameBook`を検索し、現在の状況とプレイヤーの入力に関連する情報を取得します。
    c. **L1**: `Constitution`を使い、上記(a)(b)とプレイヤーの入力を統合した**リッチなプロンプト**を生成します。
3.  **AI応答 (`controller.py` & `google-generativeai`)**: 生成したプロンプトをGeminiモデルに送信します。
    - AIはプロンプト（憲法）に基づき、必要に応じて`MCP`や`Policy`のメソッドを**ツール（関数）**として呼び出し、L2の状態を更新します。
    - `google-generativeai`ライブラリが関数呼び出しを自動処理します。
    - 最終的に、AIはプレイヤーに表示するための**テキスト応答**を生成します。
4.  **表示 (`engine.py` & `view.py`)**: AIからの最終的なテキスト応答をプレイヤーに表示します。

## 3. ソースコード構成

`src/` ディレクトリ配下の各ファイルは、上記のアーキテクチャと思想に基づいて役割分担されています。

- `main.py`
  - **役割**: アプリケーションのエントリーポイント。
  - **責務**: `GameEngine`を初期化し、ゲームを開始します。

- `engine.py` (`GameEngine`)
  - **役割**: ゲーム全体のメインループを管理するオーケストレーター。
  - **責務**: 各コンポーネント(`controller`, `view`)を統括し、ゲームの開始から終了までを管理します。

- `controller.py` (`AI_ControllerMCP`)
  - **役割**: **AIの思考**そのものを担当する、アプリケーションの「脳」。
  - **責務**: L1, L2, L3を統合してプロンプトを生成し、AIとの対話（関数呼び出しを含む）を実行します。

- `model.py` (`MCP`)
  - **役割**: **L2 (短期記憶)**。ゲームの動的状態を管理します。
  - **責務**: プレイヤー、敵、シーンIDなどの状態を保持し、AIがツールとして呼び出せる更新用メソッドを提供します。

- `policy.py` (`Constitution`, `Policy`)
  - **役割**: **L1 (憲法)** と、ルールベースのツールを提供します。
  - **`Constitution`**: AIの行動原理を定義し、プロンプトを生成します。能力値チェックの実行方法や、プレイヤーの想定外の行動への対処法など、AIの思考の核となるルールが記述されています。
  - **`Policy`**: ダイスロールなど、シナリオに依存しない普遍的なルールをツールとして提供します。

- `gamebook.py` (`GameBook`)
  - **役割**: **L3 (長期記憶)**。静的なゲームデータへのアクセスを提供します。
  - **責務**: `gamebook/` ディレクトリのMarkdownファイルを読み込み、検索可能な形式で保持します。

- `view.py` (`ConsoleView`)
  - **役割**: ユーザーインターフェース。
  - **責務**: コンソールへのメッセージ表示と、プレイヤーからの入力を受け付けます。

## 4. 今後の修正・開発方針

このプロジェクトに修正を加える際は、必ず上記の**3層アーキテクチャ**を念頭に置いてください。

- **AIの基本的な振る舞いや人格を変えたい場合**: 
  - `src/policy.py` の `Constitution` クラス内の `_BASE_CONSTITUTION` を修正します。

- **AIに新しい行動（ゲーム状態の操作）を学習させたい場合**:
  1.  その行動が「動的な状態」を扱うなら `src/model.py` (`MCP`) に、「普遍的なルール」なら `src/policy.py` (`Policy`) に、メソッドを実装します。
  2.  `src/controller.py` の `AI_ControllerMCP` の `tools` リストに、新しいメソッドを追加します。
  3.  `Constitution` のプロンプトを修正し、AIが新しいツールをどのような状況で使うべきか教えます。

- **ゲームのシナリオや設定を追加・変更したい場合**:
  - コードは変更せず、`docs/03_SCENARIO_GUIDE.md` に従って `gamebook/` ディレクトリのMarkdownファイルを編集します。

- **新しいゲームメカニクス（例：魔法、スキル）を導入したい場合**:
  1.  まず、それが「静的な定義」か「動的な状態」かを判断します。
  2.  スキルのリストや説明は **L3** (`gamebook/`) に記述します。
  3.  プレイヤーがどのスキルを覚えているか、といった情報は **L2** (`MCP`) で管理します。
  4.  スキル使用の判定ルールは **L1** (`Constitution` と `Policy` ツール) で定義します。
